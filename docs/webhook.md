# Stripe Webhook 自動付与（運用メモ）

支払い完了と同時にアイテムを自動で付与する仕組みです。従来の「解除コードを
メールで送る」方式は**併用可能**で、コード入力も引き続き使えます。

## 仕組み

1. ショップの「購入する（Stripe）」リンクには、開くときに
   `?client_reference_id=<プレイヤーID>` が自動で付きます。
2. 支払いが完了すると Stripe が `POST /webhooks/stripe` に
   `checkout.session.completed` イベントを送ります。
3. サーバーは署名を検証し、`client_reference_id` のプレイヤーへ、
   購入したアイテムを付与します。付与内容の判定は **price ID が優先**、
   金額は補助です（次節）。

## 付与内容の判定（price ID 優先）

`server/stripe-webhook.js` の `PRICE_GRANTS`（price ID → 付与内容）が
第一の対応表です。280円のアイテムは3つあり（広告無期限廃止／
ドロー速度アップ／オートドロー）、**金額だけでは判別できない**ため、
この3つは price ID でしか付与できません。サーバーはセッションの
line items から price ID を取得します（Webhookのペイロードには通常
含まれないため、`STRIPE_SECRET_KEY` が設定されていれば Stripe API
から取得します）。

> **Stripe一括作業の際にやること**：新しく作る支払いリンク5件
> （広告無期限廃止・ドロー速度アップ・オートドロー・フルオートドロー・
> デュエリストパック）について、各リンクの **price ID を
> `PRICE_GRANTS` へ登録** してください。登録されていない price ID の
> 購入は自動付与されず、サーバーログと `stripe_events.result`
> （`skipped:unknown_amount`）に残ります。あわせて、サーバーの
> 環境変数に `STRIPE_SECRET_KEY`（line items 取得用）を設定して
> ください。
> ※デュエリストパック（1,080円）とフルオートドロー（980円）は金額が
> 一意なため、下記の金額対応表でも自動付与されます（price ID 登録は
> 確実を期すための二重化です）。

金額だけで判別できるもの（その金額のアイテムが1つだけのもの）は、
`STRIPE_GRANTS_JPY`（金額 → 付与内容）で付与されます。
**280円はこの表に含まれません。**

| 金額 | 付与 |
|---|---|
| 120円 | 300ソウル |
| 320円 | 1,000ソウル |
| 680円 | 2,500ソウル |
| 1,280円 | 5,500ソウル |
| 2,940円 | 14,000ソウル |
| 5,860円 | 30,000ソウル |
| 980円 | フルオートドロー（full_auto）※price ID でも付与可 |
| 1,080円 | デュエリストパック（広告無期限廃止＋ドロー速度アップ＋フルオートドローの同時付与）※price ID でも付与可 |

ソウル付与は残高と「総ソウル獲得数」（ランキング用累計）の両方に加算されます。
ドロー速度アップが付与された場合、速度設定は自動で「速い」になります
（対戦画面で通常速度に切り替えできます）。

### 安全策

- **署名検証**：`STRIPE_WEBHOOK_SECRET` で Stripe-Signature を検証。
  未設定のときはエンドポイント自体が 503 を返し、無効化されます。
  署名が合わないリクエストは 400 です。
- **二重付与防止**：処理したイベントIDをDBの `stripe_events` テーブルに
  記録し、Stripeからの再送・重複配信では付与をスキップします。
- **付与できない場合**（プレイヤーIDなし／存在しないプレイヤー／
  未知の金額／円以外の通貨）：付与せずサーバーログにエラーを残し、
  200 を返します（Stripeの再送ループを避けるため）。
  結果は `stripe_events.result` にも残ります
  （例：`granted:souls:1000`、`skipped:unknown_amount`）。

## ローカル検証

```bash
node scripts/test-webhook.mjs
```

署名付きのテストイベントを自前で生成して実際のサーバーに投げ、
付与（ソウル／price ID 経由の広告無期限廃止・速度アップ／980円の
フルオート）・二重防止・金額のみの280円が付与されないこと・未知金額・
プレイヤー不在・署名エラー・無効化（503）の各ケースを確認します。
実Stripeには接続しません（price ID の対応付けはテスト用の
環境変数 `STRIPE_PRICE_GRANTS` で代用します）。

## 本番化の手順（残作業）

前提：本番サイトが **https** で公開されていること
（Stripeの本番Webhookは https のURLが必須です）。

1. **Stripeダッシュボードでエンドポイントを登録**
   - Stripeダッシュボード →「開発者」→「Webhook」→「エンドポイントを追加」
   - エンドポイントURL：`https://ik1-322-21344.vs.sakura.ne.jp/webhooks/stripe`
   - リッスンするイベント：`checkout.session.completed` を選択
2. **署名シークレットをサーバーに設定**
   - 登録後に表示される署名シークレット（`whsec_...`）を控える
   - サーバー（さくらのVPS）の環境変数ファイル `/etc/doro-monsutakado.env` に
     `STRIPE_WEBHOOK_SECRET=<控えた値>` を1行追加する
   - あわせて `STRIPE_SECRET_KEY=<シークレットキー>` も追加する
     （セッションの line items から price ID を取得するために必要）
2b. **price ID を登録**
   - 支払いリンク5件（広告無期限廃止／ドロー速度アップ／オートドロー／
     フルオートドロー／デュエリストパック）の price ID を控え、
     `server/stripe-webhook.js` の `PRICE_GRANTS` に登録して
     再デプロイする（前節の注意書き参照）
3. **サービスを再起動**
   ```bash
   sudo systemctl restart doro-monsutakado
   ```
4. **確認**
   - Stripeダッシュボードの Webhook 送信ログで、テスト送信が
     200 になっていることを見る
   - 実際に少額のソウルパック（120円）を購入し、コード入力なしで
     ソウルが増えることを確認する
   - うまくいかない場合はサーバーログを確認：
     `journalctl -u doro-monsutakado | grep stripe-webhook`

### 本番化後のメモ

- 動作確認が済んだら、ショップ画面の案内文（「ご購入後、解除コードを
  メールでお送りします」）を自動付与の案内に更新すると親切です。
  解除コード方式はそのまま残るので、既に送付済みのコードも使えます。
- 支払いリンク側の変更は不要です（`client_reference_id` はリンクを
  開くときにクライアントが付けます）。
